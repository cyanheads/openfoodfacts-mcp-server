# 0.1.7 — 2026-07-05

## Fixed

- **`off_search_products` score filters** — `nutrition_grade` and `nova_group` now map to the `nutrition_grades_tags`/`nova_groups_tags` query params; the bare `nutrition_grades`/`nova_groups` keys are silently ignored by `/api/v2/search` and returned unfiltered rows. Values pass through bare (`nutrition_grades_tags=a`, not `en:a`). ([#3](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/3))
- **`off_browse_taxonomy` truncation** — truncation now gates on the filtered-match count (`matched_in_facet`) instead of the pre-filter facet size, so a filtered search — including a zero-match one — no longer falsely reports `truncated: true` against the full vocabulary total. ([#4](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/4))
- **`off_get_product` field-subset rendering** — output carries `requested_fields` when `fields` is passed; `format()` renders sections outside that subset as "Not requested" instead of "Not available"/"Not entered", so the text no longer implies Open Food Facts lacks data that simply wasn't requested. ([#5](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/5))

## Dependencies

- `@cyanheads/mcp-ts-core` ^0.10.9 → ^0.10.12
- `js-yaml` (transitive, via `depcheck`) 3.14.2 → 3.15.0 — clears [GHSA-h67p-54hq-rp68](https://github.com/nodeca/js-yaml/security/advisories/GHSA-h67p-54hq-rp68) (moderate, quadratic-complexity DoS in merge-key handling), resolved by the lockfile refresh; routine maintenance, not a source-code security fix.
