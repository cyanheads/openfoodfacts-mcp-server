# 0.5.0 — 2026-11-24

## Added

- **`bun run brands:sync`** ([#98](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/98)): regenerates the brand synonym table from openfoodfacts-server `taxonomies/brands.txt` at a recorded commit (195 groups holding 243 extra keys at `c6a9ede`). It writes nothing when two entries claim one key or a computed ID is missing from the published brands taxonomy.

## Changed

- **Mirror record version 4**: a mirror-backed server fully reloads its store on its next refresh. Until that reload completes, a tag-only search carrying `brands_tag` reads the live database (on the hosted server, about 2–5 hours after deploy: the next refresh within 3 hours, then the reload), and a page past 10 of such a search is answered from one live count: empty with the total when the matches end before it, refused as `page_out_of_range` when they reach into it.
- **`brands_tag`** ([#98](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/98)): every spelling of a brand and every other name its Open Food Facts brand entry lists (`7-Up`, `7up`, `Seven Up`) count the same products on the mirror, on a live tag search, and on a text search.
- **`query`** ([#101](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/101)): words are sent lowercased, escaped, and space-joined, and the 2.x index matches each against product and generic names only, now in each product's main language too (`langs` adds `main`); category, label, and brand wording belongs in the tag filters.
- **`nutrient_filters`** ([#101](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/101)): each bound is compared as given, decimals included, for all nine nutrients. A bound reaches only records whose indexed entry carries that nutrient (47 of 1,447 `en:skyrs` records), so a matching product can be missing; the parameter description and `text_index_snapshot` say so.
- **`additives_tag`** ([#101](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/101)): combines with `query`, `nutrient_filters`, and `ingredients_tag`; the `additives_filter_needs_tag_search` refusal is gone.
- **Upstream 400s** ([#101](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/101)): the message carries the 2.x error description, and the `upstream_rejected` hint no longer asks the caller to correct filter values.
- **`mirror_snapshot`** ([#99](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/99)): on `off_get_product`, `off_compare_products`, and `off_search_products` it says computed values are as of the record's last edit or the copy's last full reload (about every 30 days), and that a removed product can still be shown. The `not_found` outcome of the live read for fields a mirror row predates no longer bounds the removal by `mirror_as_of`.

## Removed

- **`outside_constraints`** ([#101](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/101)): removed from `off_search_products`. The text index compares nutrient bounds as given, decimals included, so no row it returns falls outside `nutrient_filters` and none is left off.

## Fixed

- **`off_search_products` text search** ([#101](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/101)): `query`, `nutrient_filters`, and `ingredients_tag` searches build against search-a-licious 2.x, where every one failed with HTTP 400 in 0.4.5. A text-search row's `brands` are the index's stored forms (a slug or the name as typed, `xx:` dropped), not display names.
- **Resumed full load** ([#98](https://github.com/cyanheads/openfoodfacts-mcp-server/issues/98)): a mirror full load resumed under a newer build records the lowest record version that built its rows, so the next refresh reloads it, and until then a filter that needs the newer version reads live.
- **Page past the end**: the `content[]` header of a page beyond the result set names the page size, as `structuredContent` does.
