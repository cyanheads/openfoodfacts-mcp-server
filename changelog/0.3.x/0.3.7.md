# 0.3.7 — 2026-10-08

## Added

- **`LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`** — failed-call payload logging and opt-in OTLP log export arrive with mcp-ts-core 0.13.8, both off by default. `.env.example` documents all three plus the `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` / `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` overrides; the README lists `LOG_TOOL_FAILURE_PAYLOADS`.

## Changed

- **Tool inputs are repaired before validation** — an integer sent for a string field becomes its digits (mcp-ts-core 0.13.9: `"barcode": 3017620422003` returns the product), and a numeric or boolean string for a number or boolean field, a lone string for a list field, and `null` for an optional field are repaired (0.13.14: `"page": "2"`, `"fields": "nova_group"`, `"exclude_allergens": "en:nuts"`, `"limit": null`).
- **Error results carry `data.requestId`**, and their text ends with `request <id>` (0.13.10).
- **Less internal detail reaches clients in error data** — server stack traces (0.13.7), request context (0.13.8), and `data.rootCause` (0.13.13).
- **`ctx.log` notifications honor `MCP_LOG_LEVEL` and mask sensitive fields** (0.13.11).
- **Recovery hints come from the declared contract** — tool and service errors no longer attach their own copy; the framework fills the hint from the reason (0.13.10). `off_compare_products` reads each `failed[]` entry's hint from its own error contract, so those entries keep their hints.
- **Upstream error reasons on `off_get_product`, `off_search_products`, and `off_compare_products` state their statuses** — `when` and `recovery` text now names 504, 408, and 425 as `upstream_timeout` and 404 as excluded from `upstream_rejected`, matching the classification the code already applied. Documentation only; no behavior change.
- **Debug logs no longer include the request URL** for product fetches, tag searches, and taxonomy lookups.
- **Docker image builds install production dependencies in a `deps` stage on the build platform** (0.13.10) and prune musl-only packages from the image (0.13.11); the base image is `oven/bun:1.4.2`.
- **Packaging and repo hygiene** — the `.mcpb` bundle excludes `tests/`, `logs/`, `.cache/`, and `docs/idea.md`; `.env*` files are Docker-ignored and git-ignored (except `.env.example`, `.env.template`, and `.env.sample`); `dist/*.mcpb` stays out of the npm tarball; CodeQL runs per language under its own category; framework skills and tooling scripts are re-synced to 0.13.14.

## Fixed

- **The registry's `streamable-http` install entry starts the HTTP transport** — `server.json` no longer passes `run start:stdio` / `run start:http` to the package bin, which ignores them, so a registry client launching the HTTP entry got stdio. The entry now sets `MCP_TRANSPORT_TYPE=http`; `runtimeHint` is `npx` (cyanheads/mcp-ts-core#622).
